# تقرير مشروع PhishGuard

## 1. المشكلة

التصيد الاحتيالي أحد أساليب الهندسة الاجتماعية التي تعتمد على إقناع المستخدم بفتح رابط أو إدخال بيانات حساسة في صفحة أو رسالة تبدو موثوقة. تكمن الصعوبة في أن المستخدم يحتاج إلى قرار سريع، بينما قد يخفي الرابط وجهته أو يستخدم اسم علامة تجارية أو لغة استعجال وتهديد.

## 2. فكرة المشروع

PhishGuard أداة CLI محلية تفحص ثلاثة أنواع من المدخلات: رابط واحد، نص رسالة أو بلاغ، وملف نصي. يحلل المحرك المدخل باستخدام قواعد واضحة، ثم يجمع النقاط المرتبطة بالمؤشرات ويصدر قراراً من أربع درجات. يرفق القرار بتفاصيل كل قاعدة، حتى يستطيع المستخدم أو المناقش فهم سبب التصنيف.

## 3. أهداف المشروع

الهدف الأول هو بناء أداة عملية تعمل دون مكتبات خارجية وبأمر تشغيل موحد. والهدف الثاني هو تقديم نتيجة قابلة للتفسير بدلاً من صندوق أسود. والهدف الثالث هو دعم الفحص الفردي والدفعي من CSV والتصدير إلى JSON. والهدف الرابع هو حماية بيانات المستخدم من خلال إبقاء الفحص محلياً وعدم فتح الروابط أو إرسالها عبر الشبكة. أما الهدف الخامس فهو تقديم أساس قابل للتطوير في نسخة إنتاجية لاحقة.

## 4. التصميم العام

يتكون النظام من طبقات صغيرة مستقلة. تستقبل طبقة CLI الأمر وتتحقق من المدخلات، ثم تستدعي طبقة الفحص التي تختار مسار الرابط أو النص أو الملف. تستدعي طبقة القواعد مؤشرات URL والنص، وبعد ذلك تحسب طبقة النماذج درجة الخطر والثقة والقرار. وأخيراً تعرض طبقة الإخراج النتيجة في جدول أو JSON، مع دعم حفظها في ملف.

| المكوّن | الوظيفة | سبب الفصل |
|---|---|---|
| `cli.py` | الأوامر والمساعدة ورموز الخروج | واجهة مستقرة للمستخدم |
| `scanner.py` | قراءة الهدف وتحليل فردي/دفعي | فصل تدفق الفحص عن العرض |
| `rules.py` | قواعد التصيد | سهولة الشرح وإضافة قواعد جديدة |
| `models.py` | نتيجة موحدة ومؤشرات | مخرجات ثابتة لكل أنواع الإدخال |
| `config.py` | إعدادات JSON والسجلات | التحكم دون تعديل الشيفرة |

## 5. قواعد الكشف

تغطي القواعد خصائص الرابط مثل HTTP غير المشفر، عنوان IP المباشر، رمز `@`، Punycode، خدمات الاختصار، الامتدادات منخفضة الثقة، كثرة النطاقات الفرعية، طول الرابط، الترميز الخاص، تقليد العلامة التجارية، ومسار بيانات الدخول. كما تغطي النصوص عبارات الاستعجال وطلبات كلمة المرور والموضوعات المالية وكثرة الروابط.

لا تعتبر القاعدة الواحدة دليلاً قاطعاً؛ لذلك يستخدم النظام تجميع النقاط. هذا التصميم يقلل القرارات الحادة المبنية على مؤشر منفرد، ويعطي المستخدم تفسيراً متوازناً.

| القرار | النطاق | الإجراء المقترح |
|---|---:|---|
| `SAFE` | 0–24 | يمكن المتابعة بحذر مع بقاء التحقق البشري مهماً. |
| `SUSPICIOUS` | 25–54 | تحقق من المصدر والوجهة قبل أي تفاعل. |
| `HIGH_RISK` | 55–79 | لا تفتح الرابط ولا تدخل بياناتك. |
| `CRITICAL` | 80–100 | تعامل معه كتصيد محتمل جداً، وبلّغ المسؤول. |

## 6. الأمان ومعالجة الأخطاء

لا يفتح PhishGuard أي رابط ولا يجري اتصالاً شبكياً في النسخة الحالية. يفحص الملفات النصية فقط، ويتحقق من وجود الملف ونوعه وحجمه وترميزه. كما يتحقق من JSON، ويدير الحالات الشائعة مثل الرابط غير الصحيح، الملف غير الموجود، المسار الذي يشير إلى مجلد، عدم وجود الصلاحية، وملف الإعدادات التالف. تظهر للمستخدم رسالة عربية مختصرة بدلاً من traceback داخلي.

## 7. التشغيل العملي

يبدأ العرض بالأمر التالي:

```bash
python run.py --help
```

ثم يعرض الطالب فحص رابط آمن:

```bash
python run.py scan --url "https://example.com/about"
```

بعد ذلك يعرض حالة مشبوهة:

```bash
python run.py scan --url "http://192.168.1.10/login?password=demo"
```

وأخيراً يعرض الفحص الدفعي:

```bash
python run.py batch examples/targets.csv
```

يمكن إظهار التكامل مع البرامج الأخرى عبر JSON:

```bash
python run.py scan --file examples/suspicious_message.eml --format json
```

## 8. النتائج والمخرجات

ينتج النظام قراراً ودرجة خطر ومؤشرات تفسيرية وبيانات وصفية. في الفحص الدفعي يعرض ملخصاً يوضح العدد الكلي ومتوسط الخطر وتوزيع القرارات وعدد العناصر عالية الخطورة. وفي JSON يمكن حفظ النتيجة واستخدامها في نظام بلاغات أو لوحة مراقبة لاحقاً.

## 9. حدود المشروع

لا تقدم القواعد المحلية الحالية حكماً نهائياً على سمعة الموقع ولا تحلل JavaScript أو محتوى الصفحة بعد فتحها. هذا القيد مقصود في النسخة التعليمية للحفاظ على الخصوصية، وتجنب المخاطر التشغيلية، والالتزام بـ Pure Python دون مكتبات خارجية. النسخة الإنتاجية المقترحة يمكن أن تضيف خدمة سمعة اختيارية، محلل HTML معزولاً، قائمة سماح مؤسسية، وسجل تدقيق مركزي.

## 10. خاتمة

PhishGuard يحول مشكلة أمنية شائعة إلى أداة عملية قابلة للتجربة والشرح. قوته الأساسية هي الجمع بين سهولة التشغيل، التوافق، الخصوصية، وقابلية تفسير القرار. كما أن تصميمه المعياري يسمح بإضافة قواعد أو واجهة أخرى دون إعادة بناء النواة.
