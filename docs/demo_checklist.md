# خطة العرض العملي

## التسلسل المقترح

يبدأ العرض بشرح أن PhishGuard لا يفتح الروابط ولا يرسل المحتوى إلى الشبكة، ثم يشغّل الطالب `python run.py --help` لإظهار الأوامر والخيارات. بعد ذلك يعرض رابطاً آمناً، ثم رابطاً يستخدم HTTP وعنوان IP ومسار تسجيل دخول، ثم يشرح كيف ظهرت المؤشرات وارتفعت الدرجة. في الجزء الثالث يفحص ملف `examples/suspicious_message.eml`، وفي الجزء الأخير يشغّل فحص CSV ويعرض الملخص والتوزيع.

## أوامر العرض

```bash
python run.py --version
python run.py --help
python run.py scan --url "https://example.com/about"
python run.py scan --url "http://192.168.1.10/login?password=demo"
python run.py scan --file examples/suspicious_message.eml
python run.py batch examples/targets.csv
python run.py batch examples/targets.csv --format json --output batch-result.json
python -m unittest discover -s tests -v
```

## نقاط يجب شرحها أثناء المناقشة

يجب توضيح أن القرار لا يأتي من اتصال بخدمة خارجية، بل من قواعد محلية قابلة للفهم. كما يجب شرح أن درجة الثقة في النسخة الحالية **تفسيرية** وليست احتمالاً إحصائياً، وأن `SAFE` يعني عدم اكتشاف مؤشرات ضمن القواعد الحالية وليس ضماناً مطلقاً. ومن المهم شرح سبب استخدام رمز خروج `2` للحالات عالية الخطورة حتى يمكن استدعاء الأداة من سكربتات أخرى.

## أسئلة متوقعة وإجابات مختصرة

| السؤال | الإجابة |
|---|---|
| لماذا لم تستخدم مكتبة خارجية؟ | لأن الضابط يشترط Pure Python، ولإثبات إمكانية بناء نواة عملية بالمكتبة القياسية. |
| هل يفتح البرنامج الرابط؟ | لا. الفحص محلي بالكامل، ويحلل تركيب الرابط والنص فقط. |
| هل يمكن الاعتماد على النتيجة وحدها؟ | لا. الأداة للفرز والتوعية، والقرار الأمني النهائي يحتاج تحققاً بشرياً ومصادر مؤسسية. |
| كيف تضيف قاعدة جديدة؟ | تُضاف دالة تعيد `Finding` ثم تُدرج في `URL_RULES` أو `TEXT_RULES` وتُختبر. |
| ماذا يحدث عند ملف غير موجود؟ | تظهر رسالة واضحة ويُعاد رمز خروج `1` دون إظهار traceback. |
| كيف يدعم Windows؟ | يستخدم `pathlib` للمسارات، ولا يعتمد على أوامر نظام خاصة داخل النواة. |
